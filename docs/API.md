# API Reference

Base URL: wherever `uvicorn api.app:app` is served (`http://127.0.0.1:8000` locally). Interactive
docs are auto-generated by FastAPI at `/docs`.

## Auth

Every route below requires `Authorization: Bearer <supabase-jwt>` **except** `/health` and
`GET /source/{filename}` (see that route's own section). The server verifies the JWT against
Supabase's public JWKS endpoint (`api/deps.py`) — there's no shared secret and no `STORAGE_MODE=local`
bypass, since Auth is a separate Supabase product from Postgres/Storage.

A 404 (not 403) is returned for any resource that doesn't exist *or* belongs to another user
(`api/authz.py`) — a non-owner can't distinguish "not found" from "not yours" by status code alone.

Two routes carry an additional per-user rate limit (`src/core/rate_limiter.py`, in-memory sliding
window, not shared across processes):

| Route | Limit |
|:--|:--|
| `POST /conversations/{id}/messages`, `POST /conversations/{id}/messages/stream` | 20 / 60s |
| `POST /upload`, `POST /documents/{doc_id}/reingest` | 5 / 60s |

## Health

### `GET /health`

No auth required. Checks storage connectivity and reports the active configuration.

```json
{
  "status": "ok",                  // or "degraded"
  "storage_mode": "local",
  "chat_model": "gemini-2.5-flash",
  "storage": { "ok": true }
}
```
Returns **503** instead of 200 when `storage.ok` is `false`.

## Documents

### `GET /documents?limit=30&cursor=<opaque>`

Paginated list of the caller's own uploads plus shared/demo documents
(`docs/fixtures/sample_docs/`, `user_id IS NULL`). `limit` is clamped to 1–100.

### `POST /upload`

`multipart/form-data`, field `file`. Rate-limited (see above). Runs the same ingestion pipeline as
`scripts/ingest.py` — tree-aware parsing, hash-based dedup. Parsing/chunking happens inline;
embedding happens in a background task, since large files were previously holding the request open
for 25+ minutes.

| Outcome | Status | Body |
|:--|:--|:--|
| New/changed content | **202** | `{"status": "processing", "doc_id": ..., "analytics": {"chunk_count": N}}` |
| Byte-identical re-upload (hash match) | 200 | `{"status": "unchanged", "doc_id": ..., "analytics": {"chunk_count": 0}}` |
| Unsupported extension | 400 | — |
| Empty / unchunkable content | 400 | — |
| Over 50MB | 413 | — |
| Filename already used by another document/user | 409 | — |

Poll `GET /documents/{doc_id}/status` or stream `GET /documents/{doc_id}/events` for ingestion
progress; `"status"` resolves to `"ready"` or `"failed"`.

### `PATCH /documents/{doc_id}`

Body: `{"filename": "new-name.pdf"}`. Owner-only (403 on a shared/demo document — it has no single
owner to attribute the mutation to). The file extension can't change. `doc_id` and every chunk/
entity/conversation reference keyed by it are untouched, so existing citations keep working.

### `DELETE /documents/{doc_id}`

Owner-only. Removes the document row, its chunks/nodes/entities/edges, the stored file, and any
response-cache entries scoped to it. Conversations that already reference the `doc_id` are left as-is.

### `POST /documents/{doc_id}/reingest`

Owner-only. Re-runs ingestion against the already-stored file, bypassing the hash-based "unchanged"
short-circuit. The document's existing chunks stay live and queryable until every new chunk's
embedding has succeeded — a failed re-embed leaves the previous working version intact instead of
zeroing it out (#46).

### `GET /documents/{doc_id}/status`

```json
{ "status": "processing", "chunk_count": 42, ... }
```

### `GET /documents/{doc_id}/events`

Server-Sent Events. One `data:` frame per status change, same shape as `GET .../status`; closes the
stream once `status` reaches `"ready"` or `"failed"`.

### `GET /source/{filename}?token=<signed>`

**No bearer auth** — opened via plain `<a href>` navigation for citation links, which can't attach a
custom header. Ownership is enforced instead by a signed, 600-second-TTL token
(`src/core/security.py`) minted server-side wherever a citation or graph-section link is built.
Returns the raw file (`FileResponse`); the UI appends `#page=N` for PDFs, which browser-native
viewers honor directly.

## Conversations

A conversation is scoped to 1–5 documents (`MAX_CONVERSATION_DOCS`) — not a global search box.

### `POST /conversations`

Body: `{"doc_ids": ["doc-1"]}` (0–5 ids). An empty list resolves to the caller's own already-indexed
documents, or the shared demo corpus for a brand-new account — starting a chat never requires
picking a document first.

### `GET /conversations?limit=30&cursor=<opaque>`

Lightweight, keyset-paginated sidebar list: `{id, title, pinned, created_at, updated_at}` per row —
no `doc_ids`/filenames (that's a second query only the detail view pays for).

### `GET /conversations/{id}`

Full detail: `{"conversation": {...}, "messages": [...]}`, including each message's `sources` and
`faithfulness_score`.

### `PATCH /conversations/{id}`

Body: `{"title": "...", "pinned": true}` — either field, both optional. Used for rename/pin.

### `DELETE /conversations/{id}`

### `POST /conversations/{id}/documents`

Body: `{"doc_id": "..."}`. 400 if already attached or at the 5-document cap.

### `POST /conversations/{id}/checkpoints/{message_id}/restore`

Deletes every message after `message_id`, rewinding the conversation so the user can continue from
that point. Returns `{"messages": [...]}`.

### `POST /conversations/{id}/messages`

Rate-limited. Body: `{"message": "...", "advanced_mode": true}`. Blocks until generation *and*
faithfulness judging both finish, then returns the full reply (see `ChatReplyOut` below). A pipeline
failure is a real 500 — nothing gets persisted as a fake assistant turn (#52).

### `POST /conversations/{id}/messages/stream`

Same inputs, Server-Sent Events response — what the web UI actually calls, for the
perceived-latency win of showing tokens as they generate. Frame shapes:

```
data: {"type": "token", "text": "..."}            // zero or more
data: {"type": "done", "message": {...}}          // exactly one - same shape as the non-streaming reply
data: {"type": "title", "title": "..."}            // first turn only, after "done"
data: {"type": "error", "detail": "..."}           // instead of "done", on a pipeline failure
```

**Reply shape** (`ChatReplyOut`, both routes):

```json
{
  "id": 42,
  "conversation_id": "...",
  "role": "assistant",
  "content": "...",
  "sources": [
    {"index": 1, "document": "file.pdf", "page": 3, "section": "...", "snippet": "...", "source_token": "..."}
  ],
  "faithfulness_score": 0.93,
  "created_at": "...",
  "telemetry": { "request_id": "...", "ai_calls": [...], "...": "per-stage timings" },
  "chunks_matrix": [ { "id": 1, "rerank_score": 0.9, "rrf_score": 0.03, "...": "..." } ],
  "thinking": "retrieval hops used: 1/2\n...",
  "title": null
}
```

`title` is always `null` here — title generation runs after this response is already built (a
BackgroundTask on the non-streaming route, inline-after-`"done"` on the streaming route) and is
reported separately: via the trailing `"title"` SSE frame, or by re-fetching the conversation.

## Entity Graph

Gated by `ENABLE_ENTITY_GRAPH` server-side — exploration-only, **not** consulted during retrieval or
generation (see `server/src/graph.py`'s module docstring).

### `GET /graph?doc_id=<optional>`

Co-occurrence graph for visualization. Omit `doc_id` for the full graph, scoped to the caller's own
+ shared documents (never another user's private ones).

### `GET /graph/section/{node_id}`

The source section behind one graph node, for the UI's click-to-inspect panel:

```json
{
  "doc_id": "...",
  "heading_path": ["...", "..."],
  "content": "...",
  "page": 3,
  "source_token": "..."
}
```
